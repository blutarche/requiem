# requiem v1 — player daemon, menu bar, GUI

Status: approved direction (user, 2026-10-11). This builds on slice 1 (`docs/plans/2026-10-10-core-ytm-design.md`): core, audio, YouTube Music provider, CLI.

v1 is YouTube Music plus a GUI. Spotify is deferred; see `2026-10-10-spotify-spike.md`.

## Decisions

- **D1. Two processes.** The user chose this after the GUI measurements.
  - **Player daemon `requiemd`.** It owns playback: Session, audio engine and providers. It keeps the ≤30 MiB footprint and <1% CPU budget.
  - **GUI `requiem-gui`.** It runs only while its window is open, and quits when the window closes. Playback continues.
  - **Why:**
    - No GUI measured fits 30 MiB with a window open alongside the player. Native AppKit alone is 29.5 MiB; Slint's software renderer is 66.8 MiB.
    - Closing a window frees little in any toolkit measured (AppKit, SwiftUI, Slint).
    - The Codex council ranked two processes first.
- **D2. Menu-bar indicator** (user request). On macOS, `requiemd` shows an `NSStatusItem` while it runs: the icon shows playing or paused, and a menu offers controls.
  - It also publishes macOS Now Playing (`MPNowPlayingInfoCenter`) and takes media keys (`MPRemoteCommandCenter`).
  - Linux in v1 has no tray and no MPRIS; the daemon runs headless there. Both are noted as follow-ups.
  - **Gate:** the daemon must still fit in 30 MiB with AppKit, MediaPlayer and the status item loaded.
    - A Swift spike measured a windowless `.accessory` app with a status item, menu, Now Playing and remote commands at 12.0 MiB. A Foundation-only baseline was 1.6 MiB, so the delta is about +10.4 MiB.
    - Core peaked at 15.5–17.8 MiB in the slice-1 perf gate, which puts the estimate at about 26–28 MiB. Shared framework pages may make the real number lower.
    - The daemon perf gate measures the real number. If it fails, the user decides between the status item and the budget.
    - Measured 2026-10-11 (`perf-check.sh --daemon`), after the output parks while paused and the decode thread stopped polling: peak footprint 19–22 MiB, steady-play CPU 0.65–0.76% (was 0.97–1.24%), paused about 0.05%, idle 0.00–0.10%. Both gates pass. `sample` puts most busy time in libopus decode; the status item adds about 0.07%.
    - Measured again 2026-10-11, after the status item stopped polling, the paused decode thread stopped waking and `Position` slowed to 500 ms: peak footprint 20–23.5 MiB, steady-play CPU 0.72–0.79% (0.75–0.85% before, same session), paused 0.003% and stopped 0.005% (both about 0.055% before). Interrupt wakeups: 0.3/s paused (was 5.3/s), 2.7/s playing (was 8.7/s).
- **D3. GUI: native AppKit, written in Rust through objc2.** The user chose this on 2026-10-11.
  - A spike measured the representative screen (1100×720 Retina, sidebar, search field, 200-row table, player bar, 1 Hz tick):
    - AppKit (Swift): 29.5 MiB steady and about 0.35% CPU;
    - SwiftUI: 39.5 MiB;
    - Slint software renderer: 66.8 MiB;
    - iced and egui: 52–178 MiB.
  - Rust rather than Swift: the GUI links `requiem-ipc` and `requiem-core` directly, so protocol types are never mirrored, and there is one cargo build. It loads the same frameworks as the Swift spike, so a similar footprint is expected (unmeasured until built).
  - The GUI is macOS-only in v1. On other OSes, `requiem-gui` builds a stub that prints "the GUI is macOS-only in v1; use `requiem --connect`" and exits 2. A Linux GUI is a follow-up and can reuse the view model.
  - The Codex council (blind, before the native numbers existed) ranked the two-process design first. It named an unmeasured native AppKit UI as the largest gap, and said native would win if it came in under ~35–45 MiB. It did.
- **D4. IPC.** A Unix domain socket carrying length-prefixed JSON (serde_json, already a dependency). requiem-core's `Command` and `Event` cross the wire unchanged. Details are under "IPC protocol" below.
- **D5. The CLI gains `--connect`.** It drives the daemon over IPC with the same command set. That gives a scriptable client for tests and for the daemon perf gate. Without `--connect`, the CLI still runs in-process as in slice 1.
- **D6. Theme:** Blutarche Studio Design System. The full spec is under "GUI".

## IPC protocol (version 2)

**Transport.** A Unix stream socket.

- Path: `socket_dir()/daemon.sock`, where `socket_dir()` is:
  - macOS: `<user temp dir>/requiem`. The user temp dir comes from `confstr(_CS_DARWIN_USER_TEMP_DIR)`, which is per-user and mode 0700. Don't read the `$TMPDIR` env var: it differs between Finder-launched and shell-launched processes, and between sandboxed and unsandboxed ones. Then the GUI, CLI and daemon would compute different paths.
  - Linux: `$XDG_RUNTIME_DIR/requiem`, falling back to `/tmp/requiem-<uid>`.
- Create the directory with mode 0700. If it already exists, it must be owned by the current uid and not group- or world-writable. Otherwise refuse with an error.
- The socket file is mode 0600.
- `sun_path` holds at most 104 bytes on macOS and 108 on Linux. The expected path is ~75 bytes. If the path is too long, fail with a clear error; never truncate it.
- The server checks each peer's uid and drops the connection unless it equals its own uid. Use `getpeereid` on macOS and `getsockopt(SO_PEERCRED)` on Linux.

**Framing.** Each frame is a u32 big-endian length followed by that many bytes of UTF-8 JSON.

- A frame larger than 4 MiB is a protocol error and closes the connection.
- Search results are the largest messages, at about 20 tracks.

**Messages:**

```rust
pub const PROTOCOL: u32 = 2;
pub enum Role { Gui, Cli }
pub enum ClientMsg { Hello { protocol: u32, role: Role, version: String }, Command(Command), Ping(u64) }
pub enum ServerMsg { Welcome { protocol: u32, version: String }, Incompatible { supported: u32 }, Event(Event), Raise, Pong(u64), Goodbye }
```

**Handshake.**

- The client sends `Hello`. The server answers `Welcome` if the protocols match. Otherwise it sends `Incompatible` and closes.
- After `Welcome`, the server sends a **snapshot**: replayed `Event`s that rebuild the client's state, in this order:
  1. `QueueChanged`
  2. `NowPlaying`, if a track is loaded
  3. `State`
  4. `Volume`
  5. `Position`, if a track is loaded
- After the snapshot it streams live events.
- Clients therefore consume a single `Event` stream, and the first events are not special.

**Hub.** One daemon thread owns:

- a mirror of player state, built from Session events;
- the client list;
- the command path. Every client `Command` goes through the hub thread on its way to the Session, so the hub can rewrite search ids. In-daemon controls (`Server::send`) take the same path.

New clients are handed to the hub. The hub sends the snapshot, then adds the client to the list. Because the hub thread does both, the snapshot and the live stream cannot interleave or miss events.

**Search routing.**

- Clients pick their own `req` ids. For each search, the hub assigns a global id and remembers the mapping from global id to (client, local id).
- `SearchResults` and `SearchFailed` go only to the requesting client, carrying its local id.
- Every other event is broadcast.

**Slow clients.** Each client has a writer thread and a bounded outbound queue of 256 messages.

- When a client's queue is over 64, `Position` events are dropped for it.
- When the queue is full, the client is disconnected.

**`Raise`.**

- The daemon sends `Raise` to a connected `Role::Gui` client when the menu-bar "Open requiem" item is clicked. The GUI brings its window to the front.
- If no GUI is connected, the daemon launches the GUI:
  - inside `requiem.app` (the daemon runs from its `Contents/Helpers/requiemd.app`), through Launch Services with `open <path to requiem.app>`, so activation and single-instance behave;
  - outside a bundle, by spawning the sibling executable `requiem-gui`.
- `Client::connect_or_spawn` starts the daemon detached: `setsid` in `pre_exec`, stdin from `/dev/null`, stdout and stderr to `daemon.log`. It then leaves the GUI's process group and outlives it.

**`Command::Shutdown` from a client** quits the daemon. The CLI's `shutdown-daemon` command sends it, and so does the GUI's "Quit and Stop Music" (Option+Cmd+Q); the GUI's plain Quit (Cmd+Q) closes only the window.

**`Goodbye`.** It tells a client that the daemon quit on purpose, as opposed to the connection dying.

- On an orderly stop (`Server::shutdown`, which the menu-bar Quit, `Command::Shutdown` and idle exit all end in), the hub queues `Goodbye` behind each client's pending messages and then closes the connection.
- The writers get 200 ms in total to send it. A client whose queue is full, or that doesn't read its backlog in time, is closed without it and sees a plain disconnect.
- The client reports it as `Incoming::Goodbye`. A reader gets exactly one `Goodbye` or `Disconnected` as its last message.
- Version 2 added the queue-editing commands `Remove(usize)`, `Move { from, to }` and `Clear` (0-based indices); an older peer cannot decode them, so the handshake rejects it.
- `Goodbye` is part of PROTOCOL 1. It was added before v1 shipped, and both binaries ship together, so the protocol number was not bumped.

**Version handshake.** Both binaries ship together in one bundle, so a mismatch means a stale daemon is still running. In that case the GUI shows "An older requiem player is still running. Quit it from its menu-bar icon; this window reconnects on its own." It names no menu item: the old player's may still be called "Quit requiem".

### requiem-ipc public API (the contract the GUI and CLI build against)

```rust
pub fn socket_dir() -> io::Result<PathBuf>;            // creates + validates (0700, owner)
pub fn socket_path() -> io::Result<PathBuf>;
pub enum Incoming { Event(Event), Raise, Goodbye, Disconnected(String) } // exactly one Goodbye or Disconnected, last
pub struct Client { .. }                               // Send + Sync; cheap `send`
impl Client {
    pub fn connect(path: &Path, role: Role) -> io::Result<(Client, Receiver<Incoming>)>;
    /// Connect; if nothing listens, spawn `daemon_exe` detached and retry until `timeout`.
    pub fn connect_or_spawn(daemon_exe: &Path, role: Role, timeout: Duration)
        -> io::Result<(Client, Receiver<Incoming>)>;
    pub fn send(&self, cmd: Command) -> io::Result<()>;
}
pub struct Server { .. }
impl Server {
    /// Takes the single-instance lock, binds the socket and starts the accept and hub threads.
    /// Fails with AlreadyRunning if another daemon holds the lock.
    pub fn start(session: Session, hooks: ServerHooks) -> Result<Server, ServeError>;
    pub fn send(&self, cmd: Command);                  // in-daemon controls (menu bar, media keys)
    pub fn subscribe(&self) -> Receiver<Event>;        // in-daemon observers (menu bar)
    pub fn clients(&self) -> ClientCounts;             // { gui: usize, cli: usize }
    pub fn raise_gui(&self) -> bool;                   // true if a GUI client was told to Raise
    pub fn shutdown(self);
}
pub struct ServerHooks { pub on_shutdown: Box<dyn Fn() + Send + Sync> } // daemon quits its main loop
```

**Single instance.** The server takes an exclusive `flock` on `socket_dir()/daemon.lock`. Under that lock it removes any stale socket file, then binds. A second daemon fails with `AlreadyRunning` and exits 0.

## Daemon `requiemd`

- **Main thread.**
  - macOS: it runs `requiem_macos::run(...)`, the AppKit run loop with activation policy `.accessory`, so there is no Dock icon.
  - Linux: it blocks until shutdown.
- **Startup.** It builds the provider and engine, spawns the Session, then starts the Server.
  - The engine is built before spawn, with the forwarding sink from slice 1's CLI.
- **UI wiring.** `run_platform` calls `requiem_macos::run` on the main thread on every OS (a plain wait off macOS).
  - The thread `requiem-daemon-view` feeds it views from `Server::subscribe` through `ViewTracker`.
  - The thread `requiem-daemon-actions` maps `UiAction` to `Command`. `Seek` becomes an absolute seek. `Quit` fires the same stop as `Command::Shutdown`.
  - `OpenGui` calls `Server::raise_gui`, then launches the GUI if none is connected: `open <requiem.app>` when the exe sits in a bundle, else the sibling `requiem-gui`, detached. A missing `requiem-gui` is logged to stderr.
- **Idle exit.** The daemon exits after 5 minutes in which it has both no connected clients and state `Stopped`. It does not idle-exit while paused, so the user can resume from the menu bar.
- **No persistence in v1.** The queue is lost when the daemon exits.
- **Logging.** It follows `REQUIEM_LOG`. Output goes to stderr, which the spawner appends to `socket_dir()/daemon.log`. Before each spawn, a log over 1 MiB is moved to `daemon.log.old`.
- **Perf gate.** `scripts/perf-check.sh --daemon` runs a release `requiemd`, driven by `requiem --connect --script` with the same phases as slice 1, and measures the **daemon** pid.
  - Footprint ≤ 30720 KiB. CPU limits are the same as slice 1.
  - On macOS it runs with the status item and Now Playing active.

## macOS integration `requiem-macos`

```rust
pub struct PlayerView { pub title: String, pub artists: String, pub album: Option<String>,
                        pub duration: Option<Duration>, pub position: Duration, pub state: PlayState }
pub enum UiAction { Toggle, Next, Prev, Seek(Duration), OpenGui, Quit }
/// Runs the AppKit loop on the calling (main) thread until `stop` fires.
/// `views` delivers updates (coalesce: apply only the latest per run-loop turn).
pub fn run(views: Receiver<Option<PlayerView>>, actions: Sender<UiAction>, stop: Receiver<()>);
```

**Status item.** An `NSStatusItem` with an SF Symbol template image:

- `waveform` while playing;
- `pause.fill` while paused;
- `music.note` while stopped or idle.

Its menu:

- "Title — Artists", disabled, shown when there is a track;
- separator;
- Play/Pause (its label follows the state), Next, Previous;
- separator;
- "Open requiem";
- "Quit and Stop Music", named like the window's Option+Cmd+Q item, which does the same.

**Now Playing.**

- `MPNowPlayingInfoCenter`: title, artist, album, duration, elapsed time and playback rate, plus playback state.
- Update elapsed time only on state changes and seeks, not on every `Position`. macOS extrapolates from the rate.

**Remote commands.** `MPRemoteCommandCenter` handles play, pause, togglePlayPause, nextTrack, previousTrack and changePlaybackPosition, each mapped to a `UiAction`.

**Threading.** All AppKit calls run on the main thread. Each send on `views` or `stop` is followed by `requiem_macos::wake`, which posts a block to the main dispatch queue; the block checks `stop` and applies only the latest view. Nothing polls. Main-queue blocks run in the run loop's common modes, which include menu tracking, so an open status menu still updates.

**Bundle.** `scripts/bundle-macos.sh` builds a release and assembles `target/requiem.app`:

- `Contents/MacOS/requiem-gui` (the bundle executable);
- `Contents/Helpers/requiemd.app`, a helper app with `CFBundleIdentifier dev.blutarche.requiem.player`, `CFBundleName requiem` (shown as the Now Playing source) and `LSUIElement true`. Its executable finds the shared `Contents/Frameworks` through `@executable_path/../../../../Frameworks`.
  - **Why:** with `requiemd` in the main app's `Contents/MacOS`, LaunchServices took the running daemon for the app itself. `open requiem.app` then only activated it and never started the GUI, so "Open requiem" and a Finder double-click failed while music played.
- `Contents/Info.plist` with `CFBundleIdentifier dev.blutarche.requiem` and `NSHighResolutionCapable true`;
- `LSMinimumSystemVersion`: base 14.0, because the GUI loads Lucide SVGs through `NSImage` (checked: `NSImage(data:)` parsed an SVG into `_NSSVGImageRep` and rendered it on macOS 26.6; SVG support from macOS 14 is assumed, unverified). The script raises it to the embedded libopus's own minimum: 26.0 with the current Homebrew bottle. A lower target needs libopus built with that deployment target.

It signs ad hoc (`codesign -s -`). Notarization needs a Developer ID and is out of scope.

## GUI `requiem-gui`

Native AppKit through `objc2`, on the main thread only. On other OSes the binary prints that the GUI is macOS-only in v1 and exits 2; the view model still builds and is tested there.

**Startup.**

- `Client::connect_or_spawn(<daemon>, Role::Gui, 3 s)`, where `<daemon>` is `Contents/Helpers/requiemd.app/Contents/MacOS/requiemd` inside the bundle and `<exe dir>/requiemd` in dev builds.
- On `Disconnected`, it retries `connect_or_spawn` with backoff: 0.5, 1, 2, 4 s, and at most 4 s after that. The snapshot sent on reconnect rebuilds the state, and a search that was pending is sent again.
- Banners: "Connecting to player…" before the first connection, and "Player disconnected — reconnecting…" after a loss. Each waits 800 ms, so a connect or reconnect under a second shows none. After 30 s the banner adds the last error in plain words, and "If this persists, choose Quit and Stop Music from the requiem menu-bar icon, then reopen requiem." The error reads "The player isn’t running." for a refused or missing socket, "The player stopped responding." for a timeout or a closed connection, and "The player couldn’t be reached." otherwise; the raw error goes to stderr only. A banner too long for one line wraps to two, and the pages below move down by its height. A "Player reconnected" toast follows an outage that showed its banner.
- Until connected, transport, sliders and row play/add actions are dimmed and do nothing; prev/play/next also while the queue is empty.
- On `Goodbye` (the player quit on purpose, e.g. "Quit and Stop Music" in the menu bar) the GUI quits too, rather than respawning the player.
- "Quit and Stop Music" sends `Shutdown` and stops reconnecting, then quits on the `Goodbye`, or after 3 s without one. It is disabled unless the player is connected.
- A protocol mismatch (`ErrorKind::Unsupported`) shows the out-of-date banner (see "Version handshake") and retries every 4 s, so the window connects once the old player quits.
- `Raise` activates the app and brings the window to the front.
- `--demo` fills the window with fixed fake data and starts no daemon: 30 made-up search results, a queue of 8 with index 2 current, playing at 1:23 of 3:45, volume 70. Commands update the fake state locally.
- `--view search|queue|palette` picks the view shown at start. With `--demo`, `--view empty|disconnected|toast|out-of-date` stages a state instead: no query and no results, the reconnecting banner, a `TrackFailed` toast, or the out-of-date banner.
- `--snapshot <png> [--view …]`, with `--demo`, renders the content view to a PNG and exits 0. It uses `bitmapImageRepForCachingDisplayInRect` and `cacheDisplayInRect:toBitmapImageRep:` on a window that is never shown, so it needs no screen-recording permission.
- `--smoke` is `--demo` that exits 0 after 2 s.

**View model.** A plain-Rust module: Event in, UI state out, plus Commands. It has no AppKit types, so it is unit-tested without a window, and a later Linux GUI can reuse it. It tracks which regions changed; the views update only those, and the elapsed-time label only when the displayed second changes. While the window is hidden, minimized or fully covered, nothing is rendered: the changes accumulate and are rendered once it can be seen again.

**AppKit structure.**
- Main-thread-only UI. The IPC receiver thread forwards `Incoming` to the main thread through a `dispatch` main-queue hop (or `performSelectorOnMainThread`), batching per run-loop turn.
- Views are layer-backed and draw custom backgrounds through `CALayer` properties: background color, border and corner radius. Don't use `NSVisualEffectView`.
- The window uses `NSAppearance` `darkAqua`, so native controls (scrollers, text-field cursor, menus) render dark.
- Tables are view-based `NSTableView`s with a custom `NSTableRowView` for zebra, hover and the current-row marker, and no system selection highlight or focus ring. The selected row is accent while the table has keyboard focus and neutral (line-2) otherwise; secondary cells on it turn ink-2. A focused table with no selected row shows a 2 px accent ring instead, 4 px outside its rows so it never covers the current-row marker, and clear of the player bar's border.
- Buttons draw their own 2 px focus ring (accent; ink on accent fills) when keyboard navigation gives them focus.
- Accessibility: icon buttons carry labels and tooltips ("Previous", "Play"/"Pause", "Next", "Add to queue (⌘↩)", "Dismiss"); nav items and palette rows are buttons; the seek and volume sliders are sliders with increment/decrement, whose value reads as time for seek ("1:23 of 3:45") and a percent for volume. Toasts and banners are announced to VoiceOver at high priority when they appear or their text changes, not when redrawn.
- Fonts are embedded with `include_bytes!` and registered at startup with `CTFontManagerRegisterGraphicsFont`.
- Icons are Lucide SVGs embedded as bytes, loaded with `NSImage(data:)`, marked `isTemplate = true` and tinted with `contentTintColor`. Each is decoded once per size and shared.

**Window.** Default 1100×720, minimum 800×500. Closing it quits the GUI process (`applicationShouldTerminateAfterLastWindowClosed` returns true). The GUI is a regular app with a Dock icon while open.

**Layout and theme** (Blutarche, dark first; light mode is out of v1 scope):

- **Colors:**
  - bg `#0A0A0C`, bg-2 / surface `#121216`, bg-3 `#1A1A20`, bg-4 `#24242C` (input fill);
  - line `#24242C`, line-2 `#34343F`, line-hi `#43434F`;
  - ink `#F2EFEA`, ink-2 `#C8C5BD`, muted `#8C8C94`, muted-2 `#5A5A63`;
  - chrome-bg `#07070A`, chrome-bg-2 `#0E0E14`, chrome-bg-hover `#14141A`, chrome-border `#18181E`, chrome-ink `#E8E5DE`, chrome-muted `#8A8A92`;
  - accent `#7C70F5`, accent-hi `#9088F8`, accent-soft `rgba(124,112,245,.10)`, accent-bd `rgba(124,112,245,.30)`, selection `rgba(124,112,245,.32)`;
  - accent-2 `#F0A8D0`, for data viz and range sliders only, never actions;
  - ok `#6FBE83`, bad `#E26F5C`, info `#8EE0E8`, warn `#E0B85D`.
- **Type:**
  - Inter, embedded (OFL), for all UI text. Sizes 11/12/14/16/18/20/24.
  - Weights: 400 for body and cells, 500 for labels, nav and buttons, 600 for titles.
  - Times and durations use Inter's tabular figures, through an `NSFontDescriptor` feature setting (`tnum`, or kNumberSpacingType / kMonospacedNumbersSelector).
  - JetBrains Mono (OFL) is not needed in v1.
- **Sidebar** (240 px, chrome colors, 1px chrome-border on the right):
  - The app name `requiem`, plain lowercase, 600 weight, at the top.
  - Nav items: Search and Queue, each a Lucide icon plus label. The active item gets an accent-soft background with ink text at 600. Queue shows its track count at the right edge, muted and tabular, while the queue has tracks.
- **Search view:**
  - A search field at the top: bg-4 fill, 1px line, radius 6, 36 px tall. On focus, the border turns accent with a 2 px accent ring at 25% alpha. Enter runs the search.
  - A results table:
    - Header row: uppercase 11–12 px muted text, tracking 0.12em, on bg-2. Muted rather than the spec's muted-2, which reads at 2.74:1 on bg-2. It is a custom view above the scroll view, not an `NSTableHeaderView`: on macOS 26 a table header adds the scroll-edge effect, a translucent backdrop that `cacheDisplayInRect` renders as nothing, so `--snapshot` would come out blank.
    - Body rows: zebra striping (transparent / surface), hover bg-3, 8/12 px cell padding, 1px line between rows only.
    - Columns: title (ink), artists (muted) and album (muted) at 46/30/24% of the free width, a 44 px "+" column (search only, for the hover button), and duration (right-aligned, tabular, last). Below 640 px of table width, album is hidden. A truncated cell shows its full text in an expansion tooltip on hover.
  - Playing a row (Enter or double-click) replaces the queue with that row and every result after it, then plays index 0.
  - When that replaces a non-empty queue, a "Queue replaced" toast offers "Undo". Undo restores the old queue and its current track, pauses it again if it was paused, and seeks back once that track starts. A pause sent while a track loads holds through its start, so a paused restore stays silent.
  - The undo outlives its toast: Cmd+Z (Edit > Undo Replace Queue) does the same until the queue changes again by any other means — an add, a remove, a move, a clear, another client's edit — or the undo is used. That change also dismisses the toast if it still shows. A new current track (the next one starting) keeps it. In a text field, Cmd+Z stays the field's typing undo.
  - Add to queue (Cmd/Ctrl+Enter, the context menu, or a hover "+" ghost button) appends. The row's "+" turns into a check for 1.2 s, shown even without the pointer on the row.
  - Empty state: muted icon, then "Search YouTube Music", then "Type a song, artist or album, then press Return", with no button. With no results it reads "No results", "Nothing matched “query”" and a primary "Edit search" button that focuses the field.
  - A failed search shows an inline `bad`-colored message.
- **Queue view:** the same table style. The "Queue" heading and the muted "N tracks" count at the right share a baseline. The current row gets an accent-soft background (over the darker zebra shade, on every row) and an accent 2 px marker on the left edge of the row, which stay when the row is selected; the marker turns accent-hi there to keep 3:1 against the selection. Double-click or Return plays that index; the selection stays on it, so the arrow keys, Delete and the moves carry on from there. Empty state: "Queue is empty", "Play or add a search result" and a "Go to search" button.
  - Delete (or Forward Delete) removes the selected row; the selection lands on the row that took its place, or on the new last row, so repeated Delete keeps removing. Option+Cmd+Up and Option+Cmd+Down move the selected row one place, and the selection follows it. These keys do nothing in the results table or a text field.
  - Clear Queue (Playback menu, context menu or palette) empties the queue and stops playback. A toast offers "Undo": "Queue cleared and playback stopped" when something was playing or buffering, else "Queue cleared". Undo restores the queue the same way as after "Queue replaced", and Cmd+Z (Undo Clear Queue) lasts as long. Removing a single row has no undo.
  - Each edit is sent only when the session would apply it (connected, the row in range, a move not past either end), so the session answers every one with `QueueChanged`.
- **Context menus** (right-click): queue rows offer Play, Remove from Queue, Move Up, Move Down and, after a separator, Clear Queue; result rows offer Play and Add to Queue. They act on the clicked row, not the selection, and are disabled while the player is not connected. The clicked row has a 2 px accent outline while its menu is open.
- **Player bar** (bottom, 72 px, chrome-bg-2, 1px chrome-border on top):
  - Prev, Play/Pause and Next. Play/Pause is the primary control, a 36 px accent circle with a dark icon. Prev and Next are ghost icon buttons.
  - Title (ink, 14/600) and artists (muted, 12). "Nothing playing", or a title without artists, is centred vertically.
  - A seek slider with an accent-2 fill and a line-2 track, plus elapsed and total time. The knob, shown on hover or drag, is accent-2 too. The hit area is 24 px tall; while dragging, the elapsed label shows the time the seek will land on. The total shows the track's listed duration when it has one, so the bar and the row agree.
  - A volume icon and a slider styled the same way.
  - While buffering, the time label (72 px wide) shows `Buffering…` in muted.
- **Command palette** (Cmd+K, which also closes it): a modal over a dimmed background, with a filter field and an action list. The actions are Play/Pause, Next, Previous, Play selected, Add to queue, Focus search, Show search, Show queue, Volume up, Volume down and Clear queue, each with its shortcut if it has one. Removing and moving a row act on the selection, which the palette would hide, so they are not in it. Typing filters by substring; Up/Down and the pointer move one shared selection, Enter runs, Esc closes, and Tab does nothing. An action that would do nothing now, by the same checks that enable its menu item, is dimmed, and the selection, Enter and clicks pass over it. The panel sits a fifth of the window height below the top, raised as needed to keep 16 px below it; the full list fits the 500 px minimum height.
- **Menus:**
  - requiem: About requiem, Hide requiem (Cmd+H), Hide Others (Option+Cmd+H), Show All, Quit and Stop Music (Option+Cmd+Q), Quit requiem (Cmd+Q).
  - Edit: the standard items, then Find (Cmd+F). Outside a text field, Undo (Cmd+Z) is titled "Undo Replace Queue" or "Undo Clear Queue" while there is one to undo and the player is connected, and is a disabled "Undo" otherwise. View: Search (Cmd+1), Queue (Cmd+2), Command Palette (Cmd+K).
  - Playback: Play or Pause (titled by the state), Next (Cmd+Right), Previous (Cmd+Left), Play Selected (Return), Add to Queue (Cmd+Return), Remove from Queue (Delete), Move Up (Option+Cmd+Up), Move Down (Option+Cmd+Down), Clear Queue, Volume Up (Cmd+Up), Volume Down (Cmd+Down). The arrow, Return, Delete and volume items are disabled while a text field has focus, so the field keeps its editing keys. Remove and the moves need the Queue view, a selected row and a connected player; Clear needs a non-empty queue and a connected player.
  - Window, registered as the app's Windows menu: Minimize (Cmd+M), Zoom, Close (Cmd+W), Bring All to Front.
- **Keyboard:**
  - Space toggles playback when focus is not in a text field or on a button.
  - Cmd+F focuses search; Cmd+1 and Cmd+2 show Search and Queue. Showing Search with no results focuses the field.
  - Left/Right seek ±5 s when focus is not in a text field.
  - Return plays the selected row; Cmd+Return appends a selected search result.
  - In the queue, Delete removes the selected row and Option+Cmd+Up/Down move it.
  - Esc in the search field clears it, or leaves it when already empty. Up on the first result returns to the field.
- **Toasts** (bottom-right, 24 px from the right edge and 16 px above the player bar): 4 s, dismissable, at most one at a time. The 4 s stand still while the pointer rests on the toast, and resume with the time left when it leaves. They count from when the toast is raised, even while the window can't be seen, so one that ran out meanwhile is not shown when the window comes back. While a toast shows, the tables can scroll their last rows clear of it. They report `TrackFailed` (saying whether playback skipped to the next track or stopped), `ProviderBroken`, the connection being restored, and a replaced or cleared queue (with Undo).
- **Rules:**
  - Accent appears on roughly 1 surface in 10; red/bad only for errors.
  - A primary button rests on the accent darkened 40% toward accent-deep `#5A4FC0`, keeping its white label at 4.64:1 (on the accent itself it would be 3.82:1, under AA), and hovers on accent-deep, at 6.34:1; accent-hi would leave 2.97:1. A palette row's shortcut turns ink-2 when the row is selected.
  - No emoji and no drop shadows; use borders.
  - Radius is 6 by default and 4 for badges.
  - Motion is 120–200 ms with no bounce, eased out:
    - a toast fades in rising 8 pt (200 ms) and leaves the same way, quicker (150 ms); a toast replacing a visible one fades its content out, takes the new size, and fades the new content in (120 ms each);
    - the banner fades (200 ms) while the pages below it slide on the same curve (200 ms);
    - the bar's title and artists cross-fade when they change (200 ms);
    - an added row's "+" cross-fades to its check and back (120 ms).
  - A change asked for from the keyboard applies at once: within 1 s of a key press that acted (a window key, a menu key equivalent, a field's Return) or a palette action, the toast and the bar's title change without motion, including results that arrive later, such as the next title after Cmd+Right or the toast after Return. Changes from the pointer, and automatic ones, still animate. The banner always animates, as it is never asked for.
  - With Reduce Motion on, only the fades remain. Nothing else animates: not the palette, view switches, selection, hover, the play/pause icon, progress, spinners or result refreshes. Off screen (as for `--snapshot`) changes apply at once, and so do the changes caught up on when the window can be seen again.
- **Icons:** Lucide SVGs (ISC license), embedded: play, pause, skip-back, skip-forward, search, list-music, music, volume-2, plus, check, x. Use them as template images, tinted per state.
- **Fonts and licenses:**
  - Ship the OFL texts of the embedded fonts in `crates/requiem-gui/assets/fonts/`.
  - Ship Lucide's ISC license next to the icons.
- **GUI perf (informational gate):**
  - Footprint at most 40 MiB while the window is open (the Swift AppKit spike measured 29.5 MiB).
  - GUI CPU under 1% while playing with the window visible and idle.
  - The gate is measured on the GUI pid only, and reported with the daemon's numbers.
