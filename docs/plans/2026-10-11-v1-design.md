# requiem v1 — player daemon, menu bar, GUI

Status: approved direction (user, 2026-10-11). This builds on slice 1 (`docs/plans/2026-10-10-core-ytm-design.md`): core, audio, YouTube Music provider, CLI.

v1 is YouTube Music plus a GUI. Spotify is deferred; see `2026-10-10-spotify-spike.md`.

## Decisions

- **D1. Two processes.** The user chose this after the GUI measurements.
  - **Player daemon `requiemd`.** It owns playback: Session, audio engine and providers. It keeps the ≤30 MiB footprint and <1% CPU budget.
  - **GUI `requiem-gui`.** It runs only while its window is open, and quits when the window closes. Playback continues.
  - **Why:**
    - Slint's software renderer costs 66.8 MiB at 1100×720 Retina, and hiding the window frees nothing.
    - No toolkit measured fits 30 MiB with a window open.
    - The Codex council ranked two processes first.
- **D2. Menu-bar indicator** (user request). On macOS, `requiemd` shows an `NSStatusItem` while it runs: the icon shows playing or paused, and a menu offers controls.
  - It also publishes macOS Now Playing (`MPNowPlayingInfoCenter`) and takes media keys (`MPRemoteCommandCenter`).
  - Linux in v1 has no tray and no MPRIS; the daemon runs headless there. Both are noted as follow-ups.
  - **Gate:** the daemon must still fit in 30 MiB with AppKit, MediaPlayer and the status item loaded. That is unmeasured: core peaks at 14–19 MiB, and AppKit with no window adds about 6–7 MiB. A Swift spike measures the delta before `requiem-macos` is built. If the sum exceeds ~28 MiB, the user decides between the status item and the budget.
- **D3. GUI toolkit: Slint 1.18, software renderer**, with the winit backend and accesskit.
  - Measured ~0% CPU with a 1 Hz tick, thanks to damage tracking. It had the lowest steady footprint at Retina (66.8 MiB) and the most stable one. iced wgpu swung between 52 and 147 MiB, and iced tiny-skia used 3.9% CPU.
  - Slint doesn't free memory when its window closes, but that doesn't matter here: the GUI process exits on close.
  - It is cross-platform; KICKSTART lists Linux as a primary platform.
  - License: Slint Royalty-free 2.0. requiem's own code stays MIT OR Apache-2.0.
    - The "Made with Slint" badge goes in the README.
    - The royalty-free terms also bind anyone who redistributes the `requiem-gui` binary: they inherit the attribution condition, and embedded-device use is excluded. MIT/Apache alone would not impose that. State it in the README's license section.
  - **Open:** the Codex council (blind) flagged a native AppKit/SwiftUI GUI as the largest unmeasured option. A spike is running. If native comes in at or under ~45 MiB with acceptable quality, revisit D3 before `requiem-gui` is built. `requiem-ipc` and `requiem-daemon` don't depend on this choice.
- **D4. IPC.** A Unix domain socket carrying length-prefixed JSON (serde_json, already a dependency). requiem-core's `Command` and `Event` cross the wire unchanged. Details are under "IPC protocol" below.
- **D5. The CLI gains `--connect`.** It drives the daemon over IPC with the same command set. That gives a scriptable client for tests and for the daemon perf gate. Without `--connect`, the CLI still runs in-process as in slice 1.
- **D6. Theme:** Blutarche Studio Design System. The full spec is under "GUI".

```
crates/

  requiem-audio/           unchanged

  requiem-ipc/      NEW    protocol types, framing, socket path, Client, Server hub
  requiem-daemon/   NEW    bin `requiemd`: Session + engine + ytmusic + ipc Server + platform UI
  requiem-macos/    NEW    macOS only: status item, Now Playing, media keys (objc2)
  requiem-gui/      NEW    bin `requiem-gui`: Slint UI, view model, ipc Client
  requiem-cli/             + `--connect`
```

- `requiem-ipc` depends on `requiem-core`, `serde`, `serde_json`, `crossbeam-channel` and `libc` (for peer credentials, `flock` and `confstr`). Nothing UI-related.
- `requiem-macos` depends on `objc2`, `objc2-foundation`, `objc2-app-kit` and `objc2-media-player`.
  - It must compile to an empty crate on other OSes, using `cfg(target_os = "macos")` inside the crate.
  - It must not depend on `requiem-ipc`. It takes plain channels and closures (see below).

## IPC protocol (version 1)

**Transport.** A Unix stream socket.

- Path: `socket_dir()/daemon.sock`, where `socket_dir()` is:
  - macOS: `<user temp dir>/requiem`. The user temp dir comes from `confstr(_CS_DARWIN_USER_TEMP_DIR)`, which is per-user and mode 0700. Don't read the `$TMPDIR` env var: it differs between Finder-launched and shell-launched processes, and between sandboxed and unsandboxed ones. Then the GUI, CLI and daemon would compute different paths.
  - Linux: `$XDG_RUNTIME_DIR/requiem`, falling back to `/tmp/requiem-<uid>`.
- Create the directory with mode 0700. If it already exists, it must be owned by the current uid and not group- or world-writable. Otherwise refuse with an error.
- The socket file is mode 0600.
- `sun_path` holds at most 104 bytes on macOS and 108 on Linux. The expected path is ~75 bytes. If the path is too long, fail with a clear error; never truncate it.
- The server checks each peer's uid and drops the connection unless it equals its own uid. Use `getpeereid` on macOS and `getsockopt(SO_PEERCRED)` on Linux.

**Framing.** Each frame is a u32 big-endian length followed by that many bytes of UTF-8 JSON.

- A frame larger than 4 MiB is a protocol error and closes the connection.
- Search results are the largest messages, at about 20 tracks.

**Messages:**

```rust
pub const PROTOCOL: u32 = 1;
pub enum Role { Gui, Cli }
pub enum ClientMsg { Hello { protocol: u32, role: Role, version: String }, Command(Command), Ping(u64) }
pub enum ServerMsg { Welcome { protocol: u32, version: String }, Incompatible { supported: u32 }, Event(Event), Raise, Pong(u64) }
```

**Handshake.**

- The client sends `Hello`. The server answers `Welcome` if the protocols match. Otherwise it sends `Incompatible` and closes.
- After `Welcome`, the server sends a **snapshot**: replayed `Event`s that rebuild the client's state, in this order:
  1. `QueueChanged`
  2. `NowPlaying`, if a track is loaded
  3. `State`
  4. `Volume`
  5. `Position`, if a track is loaded
- After the snapshot it streams live events.
- Clients therefore consume a single `Event` stream, and the first events are not special.

**Hub.** One daemon thread owns:

- a mirror of player state, built from Session events;
- the client list;
- the command path. Every client `Command` goes through the hub thread on its way to the Session, so the hub can rewrite search ids. In-daemon controls (`Server::send`) take the same path.

New clients are handed to the hub. The hub sends the snapshot, then adds the client to the list. Because the hub thread does both, the snapshot and the live stream cannot interleave or miss events.

**Search routing.**

- Clients pick their own `req` ids. For each search, the hub assigns a global id and remembers the mapping from global id to (client, local id).
- `SearchResults` and `SearchFailed` go only to the requesting client, carrying its local id.
- Every other event is broadcast.

**Slow clients.** Each client has a writer thread and a bounded outbound queue of 256 messages.

- When a client's queue is over 64, `Position` events are dropped for it.
- When the queue is full, the client is disconnected.

**`Raise`.**

- The daemon sends `Raise` to a connected `Role::Gui` client when the menu-bar "Open requiem" item is clicked. The GUI brings its window to the front.
- If no GUI is connected, the daemon launches the GUI:
  - inside `requiem.app`, through Launch Services (`open -b dev.blutarche.requiem`, or `NSWorkspace`), so activation and single-instance behave (verify this during the macOS slice);
  - outside a bundle, by spawning the sibling executable `requiem-gui`.
- `Client::connect_or_spawn` starts the daemon detached: `setsid` in `pre_exec`, stdin from `/dev/null`, stdout and stderr to `daemon.log`. It then leaves the GUI's process group and outlives it.

**`Command::Shutdown` from a client** quits the daemon. The GUI never sends it; the CLI's `shutdown-daemon` command does.

**Version handshake.** Both binaries ship together in one bundle, so a mismatch means a stale daemon is still running. In that case the GUI shows "player is out of date — quit it from the menu bar".

### requiem-ipc public API (the contract the GUI and CLI build against)

```rust
pub fn socket_dir() -> io::Result<PathBuf>;            // creates + validates (0700, owner)
pub fn socket_path() -> io::Result<PathBuf>;
pub enum Incoming { Event(Event), Raise, Disconnected(String) }
pub struct Client { .. }                               // Send + Sync; cheap `send`
impl Client {
    pub fn connect(path: &Path, role: Role) -> io::Result<(Client, Receiver<Incoming>)>;
    /// Connect; if nothing listens, spawn `daemon_exe` detached and retry until `timeout`.
    pub fn connect_or_spawn(daemon_exe: &Path, role: Role, timeout: Duration)
        -> io::Result<(Client, Receiver<Incoming>)>;
    pub fn send(&self, cmd: Command) -> io::Result<()>;
}
pub struct Server { .. }
impl Server {
    /// Takes the single-instance lock, binds the socket and starts the accept and hub threads.
    /// Fails with AlreadyRunning if another daemon holds the lock.
    pub fn start(session: Session, hooks: ServerHooks) -> Result<Server, ServeError>;
    pub fn send(&self, cmd: Command);                  // in-daemon controls (menu bar, media keys)
    pub fn subscribe(&self) -> Receiver<Event>;        // in-daemon observers (menu bar)
    pub fn clients(&self) -> ClientCounts;             // { gui: usize, cli: usize }
    pub fn raise_gui(&self) -> bool;                   // true if a GUI client was told to Raise
    pub fn shutdown(self);
}
pub struct ServerHooks { pub on_shutdown: Box<dyn Fn() + Send + Sync> } // daemon quits its main loop
```

**Single instance.** The server takes an exclusive `flock` on `socket_dir()/daemon.lock`. Under that lock it removes any stale socket file, then binds. A second daemon fails with `AlreadyRunning` and exits 0.

## Daemon `requiemd`

- **Main thread.**
  - macOS: it runs `requiem_macos::run(...)`, the AppKit run loop with activation policy `.accessory`, so there is no Dock icon.
  - Linux: it blocks until shutdown.
- **Startup.** It builds the provider and engine, spawns the Session, then starts the Server.
  - The engine is built before spawn, with the forwarding sink from slice 1's CLI.
- **Idle exit.** The daemon exits after 5 minutes in which it has both no connected clients and state `Stopped`. It does not idle-exit while paused, so the user can resume from the menu bar.
- **No persistence in v1.** The queue is lost when the daemon exits.
- **Logging.** It follows `REQUIEM_LOG`. Output goes to stderr, which the spawner redirects to `socket_dir()/daemon.log`, truncated at each start.
- **Perf gate.** `scripts/perf-check.sh --daemon` runs a release `requiemd`, driven by `requiem --connect --script` with the same phases as slice 1, and measures the **daemon** pid.
  - Footprint ≤ 30720 KiB. CPU limits are the same as slice 1.
  - On macOS it runs with the status item and Now Playing active.

## macOS integration `requiem-macos`

```rust
pub struct PlayerView { pub title: String, pub artists: String, pub album: Option<String>,
                        pub duration: Option<Duration>, pub position: Duration, pub state: PlayState }
pub enum UiAction { Toggle, Next, Prev, Seek(Duration), OpenGui, Quit }
/// Runs the AppKit loop on the calling (main) thread until `stop` fires.
/// `views` delivers updates (coalesce: apply only the latest per run-loop turn).
pub fn run(views: Receiver<Option<PlayerView>>, actions: Sender<UiAction>, stop: Receiver<()>);
```

**Status item.** An `NSStatusItem` with an SF Symbol template image:

- `waveform` while playing;
- `pause.fill` while paused;
- `music.note` while stopped or idle.

Its menu:

- "Title — Artists", disabled, shown when there is a track;
- separator;
- Play/Pause (its label follows the state), Next, Previous;
- separator;
- "Open requiem";
- "Quit requiem".

**Now Playing.**

- `MPNowPlayingInfoCenter`: title, artist, album, duration, elapsed time and playback rate, plus playback state.
- Update elapsed time only on state changes and seeks, not every 250 ms. macOS extrapolates from the rate.

**Remote commands.** `MPRemoteCommandCenter` handles play, pause, togglePlayPause, nextTrack, previousTrack and changePlaybackPosition, each mapped to a `UiAction`.

**Threading.** All AppKit calls run on the main thread. The run loop drains `views` with a run-loop timer or source, at most every 250 ms. It does not poll faster than that.

**Bundle.** `scripts/bundle-macos.sh` builds a release and assembles `target/requiem.app`:

- `Contents/MacOS/requiem-gui` (the bundle executable) and `Contents/MacOS/requiemd`;
- `Contents/Info.plist` with `CFBundleIdentifier dev.blutarche.requiem` and `NSHighResolutionCapable true`;
- `LSMinimumSystemVersion` 13.0.

It signs ad hoc (`codesign -s -`). Notarization needs a Developer ID and is out of scope.

## GUI `requiem-gui`

Native AppKit through `objc2`, on the main thread only. On other OSes the binary prints that the GUI is macOS-only in v1 and exits 2; the view model still builds and is tested there.

**Startup.**

- `Client::connect_or_spawn(<exe dir>/requiemd, Role::Gui, 3 s)`.
- On `Disconnected`, it shows a "Player disconnected — reconnecting…" banner and retries `connect_or_spawn` with backoff: 0.5, 1, 2, 4 s, and at most 4 s after that. The snapshot sent on reconnect rebuilds the state.
- A protocol mismatch (`ErrorKind::Unsupported`) shows "player is out of date — quit it from the menu bar" and does not retry.
- `Raise` activates the app and brings the window to the front.
- `--demo` fills the window with fixed fake data and starts no daemon: 30 made-up search results, a queue of 8 with index 2 current, playing at 1:23 of 3:45, volume 70. Commands update the fake state locally.
- `--view search|queue|palette` picks the view shown at start. With `--demo`, `--view empty|disconnected|toast|out-of-date` stages a state instead: no query and no results, the reconnecting banner, a `TrackFailed` toast, or the out-of-date banner.
- `--snapshot <png> [--view …]`, with `--demo`, renders the content view to a PNG and exits 0. It uses `bitmapImageRepForCachingDisplayInRect` and `cacheDisplayInRect:toBitmapImageRep:` on a window that is never shown, so it needs no screen-recording permission.
- `--smoke` is `--demo` that exits 0 after 2 s.

**View model.** A plain-Rust module: Event in, UI state out, plus Commands. It has no AppKit types, so it is unit-tested without a window. It tracks which regions changed; the views update only those, and the elapsed-time label only when the displayed second changes.

**Window.** Default 1100×720, minimum 800×500. Closing it quits the GUI process.

**Layout and theme** (Blutarche, dark first; light mode is out of v1 scope):

- **Colors:**
  - bg `#0A0A0C`, bg-2 / surface `#121216`, bg-3 `#1A1A20`, bg-4 `#24242C` (input fill);
  - line `#24242C`, line-2 `#34343F`, line-hi `#43434F`;
  - ink `#F2EFEA`, ink-2 `#C8C5BD`, muted `#8C8C94`, muted-2 `#5A5A63`;
  - chrome-bg `#07070A`, chrome-bg-2 `#0E0E14`, chrome-bg-hover `#14141A`, chrome-border `#18181E`, chrome-ink `#E8E5DE`, chrome-muted `#8A8A92`;
  - accent `#7C70F5`, accent-hi `#9088F8`, accent-soft `rgba(124,112,245,.10)`, accent-bd `rgba(124,112,245,.30)`, selection `rgba(124,112,245,.32)`;
  - accent-2 `#F0A8D0`, for data viz and range sliders only, never actions;
  - ok `#6FBE83`, bad `#E26F5C`, info `#8EE0E8`, warn `#E0B85D`.
- **Type:**
  - Inter, embedded (OFL), for all UI text. Sizes 11/12/14/16/18/20/24.
  - Weights: 400 for body and cells, 500 for labels, nav and buttons, 600 for titles.
  - Times and durations use Inter's tabular figures, through an `NSFontDescriptor` feature setting.
- **Sidebar** (240 px, chrome colors, 1px chrome-border on the right):
  - The app name `requiem`, plain lowercase, 600 weight, at the top.
  - Nav items: Search and Queue, each a Lucide icon plus label. The active item gets an accent-soft background with ink text at 600.
- **Search view:**
  - A search field at the top: bg-4 fill, 1px line, radius 6, 36 px tall. On focus, the border turns accent with a 2 px accent ring at 25% alpha. Enter runs the search.
  - A results table:
    - Header row: uppercase 11–12 px muted-2 text, tracking 0.12em, on bg-2. It is a custom view above the scroll view, not an `NSTableHeaderView`: on macOS 26 a table header adds the scroll-edge effect, a translucent backdrop that `cacheDisplayInRect` renders as nothing, so `--snapshot` would come out blank.
    - Body rows: zebra striping (transparent / surface), hover bg-3, 8/12 px cell padding, 1px line between rows only.
    - Columns: title (ink), artists (muted), album (muted), the hover "+" (search only), duration (right-aligned, tabular, last).
  - Playing a row (Enter or double-click) replaces the queue with that row and every result after it, then plays index 0.
  - Add to queue (Cmd/Ctrl+Enter, or a hover "+" ghost button) appends.
  - Empty state: muted icon, then "Search YouTube Music", then "Type a song, artist or album", then a primary "Start a search" button that focuses the field. With no results it reads "No results", "Nothing matched “query”" and "Edit search".
  - A failed search shows an inline `bad`-colored message.
- **Queue view:** the same table style. The current row gets an accent-soft background and an accent 2 px marker on the left edge of the row. Click plays that index. Empty state: "Queue is empty", "Play or add a search result" and a "Go to search" button.
- **Player bar** (bottom, 72 px, chrome-bg-2, 1px chrome-border on top):
  - Prev, Play/Pause and Next. Play/Pause is the primary control, a 36 px accent circle with a dark icon. Prev and Next are ghost icon buttons.
  - Title (ink, 14/600) and artists (muted, 12).
  - A seek slider with an accent-2 fill and a line-2 track, plus elapsed and total time. The knob, shown on hover or drag, is accent-2 too.
  - A volume icon and a slider styled the same way.
  - While buffering, the time label shows `buffering…` in muted.
- **Command palette** (Cmd+K): a modal over a dimmed background, with a filter field and an action list. The actions are Play/Pause, Next, Previous, Focus search, Show search, Show queue, Volume up and Volume down. Typing filters by substring; Up/Down select, Enter runs, Esc closes.
- **Keyboard:**
  - Space toggles playback when focus is not in a text field.
  - Cmd+F focuses search; Cmd+1 and Cmd+2 show Search and Queue.
  - Left/Right seek ±5 s when focus is not in a text field.
  - Return plays the selected row; Cmd+Return appends a selected search result.
- **Toasts** (bottom-right): 4 s, dismissable, at most one at a time. They report `TrackFailed`, `ProviderBroken`, and the connection being lost or restored.
- **Rules:**
  - Accent appears on roughly 1 surface in 10; red/bad only for errors.
  - No emoji and no drop shadows; use borders.
  - Radius is 6 by default and 4 for badges.
  - Motion is 120–200 ms with no bounce.
- **Icons:** Lucide SVGs (ISC license), embedded: play, pause, skip-back, skip-forward, search, list-music, volume-2, plus, x. Draw them as strokes in the current color.
- **Fonts and licenses:**
  - Ship the OFL texts of the embedded fonts in `crates/requiem-gui/assets/fonts/`.
  - Ship Lucide's ISC license next to the icons.
- **GUI perf (informational gate):**
  - Footprint at most 90 MiB while the window is open (the spike measured 66.8).
  - GUI CPU under 1% while playing with the window visible and idle.
  - The gate is measured on the GUI pid only, and reported with the daemon's numbers.

## Testing

- **requiem-ipc:**
  - framing round trip;
  - oversize frame rejected;
  - handshake, including the version-mismatch path;
  - snapshot-then-live ordering;
  - per-client search routing;
  - slow-client Position drop and disconnect;
  - a second Server reports `AlreadyRunning`;
  - stale socket cleanup;
  - directory permission validation.

  These use real Unix sockets in a temp dir. If the sandbox blocks Unix binds, the tests run unsandboxed and the report says so.
- **Daemon integration.** An in-process Server over `FakeProvider` and `FakeEngine` (core `test-util`) with a real Client: search, play, events, and a reconnecting client getting the snapshot.
- **CLI.** `--connect` unit tests against an in-process Server, plus an `#[ignore]` live test that runs a real `requiemd` and plays YouTube.
- **GUI.**
  - View-model unit tests: every Event mapped to its state change, plus the search, play and append command sequences.
  - `requiem-gui --smoke` starts the app and exits 0.
  - The visual check is `--demo --snapshot` PNGs of each view, read by the lead.
- **macOS:**
  - Unit-test the `PlayerView` derivation from Events.
  - The AppKit parts get a manual check: status item, menu actions, media keys, and the Control Center Now Playing tile.
- **Linux:** the workspace builds and non-live tests pass in Docker (`rust:1.96-bookworm`). `requiem-macos` compiles to an empty crate there.
